Changelog

One repo documents one product, so this page is the product's single release history. Every user-visible change lands here, versioned with semantic versioning.

Versioning policy

Releases follow SemVer: MAJOR.MINOR.PATCH.

Major

Breaking changes: authored pages or forks need edits to keep working.

Minor

New capability, backwards compatible — new components, commands, endpoints.

Patch

Fixes and internal improvements. Nothing to change on your side.

Keeping it honest

The current version lives in assets/toc.js (product.semver) and is shown in the header badge. A release isn't done until this page and that field are updated — the AI authoring prompt treats them as one unit.

Releases

v0.7.1 2026-08-03 patch

  • Fixed The menu button on the landing page opened nothing at any width. Hiding the landing sidebar with display:none outranked the drawer rules, so the open state applied to an invisible element while the backdrop still appeared—clicking the button only dimmed the page. The landing sidebar now has real overlay-drawer styling and the button opens the full table of contents, which matters below 860 px where the landing top bar is hidden.
  • Fixed The landing layout broke between 921 px and 1023 px. The single-column shell and the menu button were declared inside a min-width:1024px query, so below it the shell fell back to the 232 px sidebar column, reserved a gutter for a hidden sidebar, and dragged the full-bleed hero off-screen with the headline clipped.

v0.7.0 2026-08-03 minor

  • Added Optional login layer for pustaka serve, enabled by PUSTAKA_AUTH with a single central credential in the environment. Sessions are a stateless HMAC-signed HttpOnly cookie whose payload fingerprints the credential pair, so changing the username or password invalidates outstanding sessions. Unset the variable and the layer disappears completely—routes are never registered and the info endpoint is unchanged.
  • Added An animated login page at docs/_login.html, served by the engine and editable in place, with a compiled-in fallback. It reuses the landing page's atmosphere—constellation canvas, layered gradients, engraved grid, pointer spotlight—and adds a password reveal, Caps Lock warning, progress and lockout states. It loads neither the registry nor the runtime, so a locked site does not hand out its table of contents.
  • Added A sign-out control in the header, injected only when the server reports that auth is on.
  • Changed The landing page and assets/ stay public when auth is on, so the site still has a front door. Everything else—pages, partials, the generated index and search—requires a session, and the check runs before the file is looked up so missing and existing pages are indistinguishable to a signed-out visitor.
  • Changed Route construction moved into a testable handler builder, and JSON responses can now carry a real status code instead of always committing 200.

v0.6.0 2026-07-31 minor

  • Added Optional declarative page metadata for display tags, hashtags, publication and update dates, and open or bounded SemVer applicability. The checker validates the complete contract when it is used.
  • Added Recursive ToC menu nodes with active-path expansion, persisted disclosure state, accessible controls, and leaf flattening for search and previous/next.
  • Added AI-friendly tutorials for Markdown conversion, page metadata, and nested sidebar navigation.
  • Added Two more Sisflow-derived guides—request-workflow and org-chart-editor—plus a DOM-first kanban board sample. The Sisflow pages keep the existing offline workbench/viewer pattern, while the board page is explicitly documented as non-canvas content.
  • Fixed Partial swaps now resolve fragment resources against the destination URL before insertion and update history before resource loading, preventing landing-page device images from resolving against the page being left.

v0.5.0 2026-07-30 minor

  • Added Distinct landing layout: <body data-layout="landing"> swaps the docs chrome for a marketing top bar (nav groups become top-level links), hides the sidebar, page-toc rail and prev/next, and enables a full-bleed hero with a CSS-generated gradient-and-grid background — no image request.
  • Added Device mockups now embed real screenshots of live pages (390 × 780 portrait, 1280 × 800 tablet), captured with a headless browser instead of hand-built CSS miniatures.
  • Added Self-hosted assets: ECharts is vendored to assets/vendor/ and the three typefaces to assets/fonts/ (woff2, latin). Pages now make zero third-party requests and render identically offline or behind a strict CSP.
  • Added pustaka.echarts() loader (vendored copy → CDN → visible .chart-fail state) and pustaka.reduced on the runtime API.
  • Fixed Live filters did nothing on most pages. The stylesheet only defined .card.hide, so filtering an admonition list applied the class but never hid anything. Replaced with a .hide state utility that works on any element type.
  • Fixed Charts silently rendered nothing when ECharts was unavailable — if (!window.echarts) return; left an empty box with no explanation. Chart pages now await the loader and surface a readable failure instead.
  • Fixed Landing chrome leaked into docs pages. data-layout lives on <body>, which partial swaps do not replace, so navigating away from the home page kept the sidebar hidden. The partial endpoint now reports layout and the runtime applies it per swap.
  • Fixed Device mockups looked empty: their contents were drawn at 6 px in --line and --faint, effectively invisible.
  • Fixed Hero background silently dropped because it referenced an undefined --bg token; substitution produced an invalid declaration. Now uses --paper, and every var() in the stylesheet is audited against the defined tokens.

v0.4.0 2026-07-30 minor

  • Added Interactive landing page: hero, device mockups that render real page miniatures in 380 px portrait and tablet landscape, an embedded live-search demo, an animated AI authoring-loop replay, and measured performance metrics.

v0.3.0 2026-07-30 minor
