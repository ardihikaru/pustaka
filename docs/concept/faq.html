FAQ

Short answers to the questions that come up when adopting an HTML-first documentation engine. Filter the list — it's live, like everything here.

Common questions

Can I migrate pages from Markdown?

Yes — follow the Markdown to HTML tutorial to render a body fragment, fit it into _template.html, repair heading ids and extension-specific components, register it, and pass pustaka check.

Does search work without the Go server?

Yes. In static mode search runs over the sections arrays in assets/toc.js. The server upgrades this automatically with an index generated from the real page text — same UI, better recall.

How do AI models write pages safely?

Give the model ai/SYSTEM_PROMPT.md and ai/AUTHORING_SPEC.md. It emits complete files; pustaka check ./docs reports spec violations, which you paste back until the check passes. This very page went through that loop.

Why Go + HTMX instead of a JS framework?

The content is HTML already, so the server only needs to move fragments: one binary, an in-memory index, and partial swaps of <main.doc>. No build step, no hydration, millisecond responses.

Do charts work offline?

Yes. ECharts is vendored at assets/vendor/echarts.min.js and loaded through pustaka.echarts(). The runtime can fall back to the CDN, but a normal build makes no third-party request and works in an air-gapped environment.

How do I deploy?

Static: push the docs/ folder to any static host — everything works minus partial swaps. Full experience: run the pustaka binary behind your reverse proxy; it serves, indexes, and gzips in one process.
