Request workflow

Model an intake-to-closure request workflow as a fixed Sisflow-derived route or as a workbench that keeps the same path while letting labels and stage notes be edited.

Live request-workflow workbench

The workbench keeps the request path fixed while stage labels remain editable. The active stage highlights the current handoff, and the demo surfaces the same progression in the details panel. Use the embedded fullscreen control for a more app-like walkthrough.

Live request-workflow viewer

The viewer locks the labels and notes but keeps the request progression and the current-step focus visible for inspection. Fullscreen gives the workflow a more continuous, rightward flow.

Fixed and read-only contract

RequirementImplementation
Keep the route fixedThe request path stays left-to-right through intake, triage, approval, fulfillment, and closure.
Block mutation in viewer modeFreeze the workbench to remove label editing and keep the viewer state read-only.
Preserve navigationStage selection, previous/next, and reset stay available so readers can inspect the same request from each step.
Keep canonical data separateThe displayed labels and descriptions are derived from one source model and re-rendered rather than mutated in place.

Complete runnable sample

The bootstrap is a small DOM app: one model, one renderer, and one mode toggle. It is intentionally separate from the canvas diagrams because the workflow sample is an interaction pattern, not a graph layout problem.

html
<!doctype html>
<meta name="viewport" content="width=device-width">
<iframe id="workflow" src="../../assets/vendor/sisflow/request-workflow-demo.html?mode=workbench"
  allow="fullscreen" style="width:100%;height:720px;border:0;border-radius:16px"></iframe>

<script type="module">
  const workflow = document.querySelector('#workflow');
  // Swap `mode=viewer` to lock the labels and hide the editor controls.
  const setMode = (mode) => { workflow.src = `../../assets/vendor/sisflow/request-workflow-demo.html?mode=${mode}`; };
  setMode('workbench');
  // setMode('viewer');
</script>

Fullscreen and embedding

Request fullscreen on the iframe or its wrapper from a click handler so the browser keeps the user activation. When the page is embedded inside another document, the parent iframe must allow fullscreen explicitly.

javascript
const frame = document.querySelector('#workflow');
toggle.onclick = () => (document.fullscreenElement ? document.exitFullscreen() : frame.requestFullscreen());

Lifecycle

Keep the workflow model as a canonical object, then rebuild the iframe or re-render from that object when the mode changes. That keeps viewer mode and workbench mode in sync without accumulating DOM edits.
