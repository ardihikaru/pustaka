Guide

Writing pages

The component vocabulary — everything mkdocs-material gives you via extensions, expressed as plain HTML classes. Each example below is rendered live.

Page structure

Author only what is unique to your page. The runtime injects everything else:

  • You write: <main class="doc"> with headings, prose, components.
  • Injected: header, sidebar drawer, search overlay, “on this page” rail (from your h2/h3 ids), ¶ anchors, prev/next, footer, back-to-top.

Admonitions

Three levels, same shape as mkdocs-material’s !!! note blocks:

Note

<div class="adm note"> — neutral context and cross-references.

Tip

<div class="adm tip"> — shortcuts and best practice.

Warning

<div class="adm warn"> — breaking changes and sharp edges.

Tabs & code blocks

Content tabs for platform-specific instructions; code blocks get a language label and a copy button wired automatically:

html
<div class="codeblock">
  <div class="bar"><span class="lang">go</span>
    <button class="copy">copy</button></div>
  <pre>fmt.Println("hi")</pre>
</div>
go
fmt.Println("hi")

Note — filter vs. search

Filter narrows what is on this page (like mkdocs-material’s tag filtering). Search (Ctrl K) looks across every page via the index in toc.js. Same matcher, different scope.
