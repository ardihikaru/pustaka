Page metadata

Add optional, machine-readable tags, hashtags, dates, and system-version applicability to any page without duplicating presentation markup.

The metadata contract

Place one empty .page-meta element after the lede. Its data attributes are the source of truth; the runtime renders accessible chips, semantic dates, and the version badge.

html
<div class="page-meta"
     data-tags="deployment, production"
     data-hashtags="deploy, operations"
     data-published="2026-07-31"
     data-updated="2026-08-04"
     data-version-from="0.6.0"
     data-version-to="0.8.x"></div>

Write comma-separated display tags without leading #. Hashtags are lowercase machine tokens containing letters, digits, and hyphens.

Version ranges

data-version-from is a full SemVer lower bound and is always required when the component is present. Leave data-version-to empty for “this version and later,” use a full upper version for an exact boundary, or use a terminal wildcard such as 0.8.x.

AttributesRendered meaning
from="0.6.0" to=""v0.6.0+
from="0.6.0" to="0.8.4"v0.6.0–v0.8.4
from="0.6.0" to="0.8.x"v0.6.0–v0.8.x

Validation

The component is optional. Once present, all fields except the upper version bound must be non-empty. The checker rejects duplicate items, invalid ISO dates, an update before publication, malformed versions, and reversed ranges.

shell
./pustaka check ./docs

Search tags are separate

The page metadata is the header source of truth. Keep the ToC leaf's tags useful too: static search reads the registry without fetching every HTML file.
