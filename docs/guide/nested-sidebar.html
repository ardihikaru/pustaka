Nested sidebar navigation

Organize large documentation sets into recursive sub-menus while preserving search, previous/next order, active-page state, and accessible controls.

Recursive schema

A page remains a leaf with the established key order. A menu is not a page: it has a stable id, a title, and a children array containing more menus or page leaves.

javascript
{
  id: "guide-components-menu",
  title: "Components",
  children: [
    {
      id: "guide-navigation-menu",
      title: "Navigation",
      children: [
        {
          id: "nested-sidebar",
          file: "guide/nested-sidebar.html",
          title: "Nested sidebar",
          desc: "Implement recursive sidebar menus.",
          tags: ["sidebar", "navigation"],
          sections: []
        }
      ]
    }
  ]
}

Runtime behavior

  • The active page’s complete ancestor path opens automatically.
  • Manual disclosure state is saved locally and shared by desktop and mobile navigation.
  • Menu buttons expose aria-expanded and their controlled region.
  • Search, top navigation, and previous/next flatten only page leaves in document order.

Stable menu ids

Use scoped ids such as guide-navigation-menu. They are persistence keys, so changing one intentionally resets that branch’s saved open state.

Migrate a flat group

  1. Choose related consecutive page leaves.
  2. Wrap them in a menu object without editing the leaves themselves.
  3. Add deeper menu wrappers where the information architecture requires them.
  4. Run the checker, then verify active-path and previous/next order in a browser.

The pustaka new command still inserts a flat leaf at the part marker. Move that complete leaf into the intended children array when nested placement is required.
